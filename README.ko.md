# 로그 스케일 태양계 (Logarithmic Solar System)

> **English:** The English version of this document is available in [README.md](README.md).

**Vite + TypeScript(strict) + Three.js**로 만든 인터랙티브 3D 태양계 데모입니다. 태양부터 명왕성까지 그리고 주요 위성들을 실측 천문 데이터를 바탕으로 렌더링하며, 로그 거리 스케일과 가시성 보강 크기 스케일을 적용해 전체 계를 한 화면에 담습니다.

## 실행 방법

```bash
npm install
npm run dev
```

출력된 로컬 URL을 브라우저에서 엽니다. 프로덕션 빌드:

```bash
npm run build   # `tsc --noEmit`(타입 체크) → `vite build` → `npm run verify` 순서로 실행
npm run preview
```

데이터셋 무결성 + 스케일 함수 불변식 검증(단독 실행):

```bash
npm run verify  # 25개 검사: 필수 천체/위성, 소스 메타데이터, 유한값,
                # 경계 조건, 단조성·순서 보존, NaN 부재
```

검증(`src/verifyCore.ts` + `scripts/verify.mjs`)은 순수 스케일 함수와 데이터셋을 esbuild로 묶어 브라우저를 띄우지 않고 모든 불변식을 검사합니다. `npm run build`의 일부로 함께 실행됩니다.

데모는 외부 런타임 에셋이 필요 없습니다. 천체는 절차적 색상, 별 필드는 절차적으로 생성합니다.

## 조작법

- **왼쪽 드래그** — 카메라 궤도 회전
- **휠 / 핀치** — 확대·축소
- **오른쪽 드래그** — 이동(pan)
- **천체 클릭** — 선택/포커스합니다(태양 = 전체 뷰, 행성 = 그 위성들, 위성 = 부모와 함께 프레이밍). 카메라는 부드럽게 이징(easing)되어 이동합니다
- **빈 공간 더블클릭 또는 Reset** — 전체 태양계 뷰로 복귀
- **← Back 버튼**(천체가 포커스된 동안 컨트롤 패널에 표시) — 행성 상세 뷰에서 전체 태양계 뷰로 복귀
- **H 키** — 전체 UI 오버레이(패널, 정보, 툴팁, 라벨) 숨김/표시

## UI 패널 표시/숨김 (H)

**H**를 누르면 단일 오버레이 스위치가 토글됩니다. HUD가 가진 모든 것 — 조작 패널, 정보 패널, 툴팁, 씬 라벨, 고지문 — 이 한 번에 숨겨집니다. 숨겨진 동안에도 3D 캔버스·애니메이션·OrbitControls 상호작용(천체 선택 포함)은 계속 동작하며, **H**를 다시 누르면 UI가 원래 상태 그대로 복원됩니다.

화면 오른쪽 하단의 고정된 **`UI 보기/숨김` 버튼**은 숨겨진 오버레이 밖에 있어 항상 접근 가능한 토글입니다. 모든 패널이 숨겨져 있어도 한 번의 클릭으로 UI를 되돌릴 수 있습니다. 숨김 상태에서는 이 버튼(과 3D 씬)만 화면에 남습니다.

작은 화면에서는 레이아웃이 반응형으로 바뀝니다. 컨트롤 패널은 축소되어 오른쪽 위로 이동하고, 정보 패널은 스크롤 가능한 하단 시트가 되며, 라벨 밀도가 줄어듭니다(작은 라벨, 보조 영어 줄 숨김, 겹치는 라벨 사이 화면 간격 확대).

## 거리·크기 스케일

데모는 **실제 천문 값**과 **렌더링 표시 값**을 별개의 개념으로 취급하며 절대 섞지 않습니다.

### 태양 중심 거리

실제 태양→행성 거리는 AU 단위의 긴반지름(semi-major axis)으로 저장됩니다. 기본 **Log** 매핑은 수성부터 명왕성까지가 뷰포트에 들어오도록 압축합니다:

```
normalized = log1p(distanceAU) / log1p(MAX_DISTANCE_AU)
rendered   = MIN_RENDER_DISTANCE + normalized * (MAX_RENDER_DISTANCE - MIN_RENDER_DISTANCE)
```

상수: `MAX_DISTANCE_AU ≈ 39.5`, `MIN_RENDER_DISTANCE = 16`, `MAX_RENDER_DISTANCE = 190` (`src/config/constants.ts`에서 조정).

선택 가능한 모드:

- **Log Scale** (기본) — 계 전체를 압축
- **Linear Scale** — 실제 비례 거리(비교를 위해 내행성이 의도대로 태양 가까이 모임)
- **Focus Scale** — 선택한 행성을 중심으로 한 국소 로그 창

### 위성 궤도 스케일

위성 궤도는 전역 거리 스케일을 재사용하지 않습니다. 각 행성계는 행성 아래에 자체 로컬 프레임을 가지며, 위성 거리는 행성의 표시 반지름의 배수(약 2.5–9배)로 매핑됩니다:

```
shifted   = max(0, distanceKm - minKm)
shiftedMax= max(1, maxKm - minKm)
norm      = log1p(shifted) / log1p(shiftedMax)
multiple  = 2.5 + norm * (9 - 2.5)
```

### 천체 크기

실제 반지름은 km 단위로 저장되지만, 작은 천체가 보이도록 렌더링 크기는 독립적으로 보강됩니다. 기본 **Enhanced** 행성 매핑:

```
ratio     = radiusKm / EARTH_RADIUS_KM
rendered  = clamp(0.55 + 0.65 * sqrt(ratio), 0.55, 4.0)
```

태양은 8 유닛으로 고정됩니다. 위성은 최소 가시 크기를 유지하도록 비슷하게 클램프된 매핑을 사용합니다. 모드: **Enhanced**(기본), **Relative**(실제 비율에 가깝게), **Uniform**(거의 일정한 마커 크기).

> **중요:** 렌더링된 천체 크기와 렌더링된 궤도 거리는 하나의 균일한 물리 스케일을 공유하지 않습니다. 실제 거리/크기 순서는 보존되지만 그 크기는 표시용으로 압축됩니다. 앱 내 고지문이 이를 명시합니다.

## 성능

데모는 일반적인 데스크톱·모바일 브라우저에서 부드러운 재생을 목표로 합니다:

- **프레임당 객체 할당 없음.** 궤도선과 천체 지오메트리는 생성 시 1회 구축 후 재사용됩니다 — 스케일/UI 모드 변경은 기존 객체를 재스케일하거나 변형만 할 뿐입니다. 애니메이션 루프는 임시 `Vector3`/`Vector2` 인스턴스를 재사용하며, 시뮬레이션 시계는 프레임 수가 아닌 실제 경과 벽시계 시간에서 진행되므로 움직임이 프레임 레이트와 무관합니다.
- **픽셀 비율 상한.** `renderer.setPixelRatio(Math.min(devicePixelRatio, 2))` 로 retina급 고DPI 디스플레이의 무제한 고해상도 렌더링 비용을 방지합니다.
- **라벨은 필요할 때만 갱신.** 라벨은 opacity + `display` 토글로 페이드·컬·숨김 처리되며 상태가 변하지 않으면 DOM을 건드리지 않습니다. 정보 패널은 선택 또는 스케일 모드 변경 시에만 다시 렌더링됩니다.
- **모바일 밀도 축소.** 모바일 브레이크포인트 아래에서는 절차적 별 필드가 약 2,900에서 820 포인트로 줄고 라벨 밀도가 낮아집니다(라벨 간 화면 간격 확대, 보조 영어 줄 숨김).
- **해제(dispose).** 모든 모듈은 지오메트리·머티리얼·텍스처·OrbitControls·렌더러·ResizeObserver·모든 이벤트 리스너를 해제하는 `dispose()`를 노출해 GPU/DOM 리소스 누수 없이 앱을 정리할 수 있습니다.

## 데이터 출처 및 정확도

천체들은 공개 NASA/JPL 행성 팩트 시트 수치(주요 긴반지름, 반지름, 이심률, 궤도 경사, 공전/자전 주기)에서 근사되었습니다. 데이터셋이 보장하는 것:

- 행성의 거리순·크기순 정확한 순서
- 공전 주기의 정확한 상대 순서
- 모든 위성의 올바른 부모 천체, 그리고 거리순 위성 배열
- 명왕성의 상대적으로 높은 이심률과 궤도 경사
- **모든** 천체에 비어 있지 않은 `source`(NASA/JPL 인용) 기록 — 출처 추적 가능

데이터 파일: `src/data/solarSystemData.ts`(태양 + 행성 8개 + 명왕성), `src/data/moonData.ts`(주요 위성). 위성 정의는 격리되어 있어 렌더링 엔진을 건드리지 않고 위성을 추가/제거할 수 있습니다 — 레코드 하나를 추가하면 본문 인덱스와 렌더러가 자동으로 인식합니다.

### 위성 선정 기준

포함된 위성은 전형적인 태양계 시각화에서 쓰이는 잘 알려진 "주요/참조" 위성들입니다: 지구의 달, 화성의 두 위성, 갈릴레이 위성, 토성의 주요 위성, 천왕성의 다섯 고전 위성, 해왕성의 트리톤, 명왕성의 다섯 알려진 위성.

## 프로젝트 구조

```
src/
  main.ts            진입점(조립만 담당)
  styles.css         레이아웃 & HUD 스타일
  types.ts           공유 도메인 타입 / 계약
  config/constants.ts  조정 가능한 모든 상수 + 카피
  data/              태양계 + 위성 데이터셋, 본문 인덱스
  core/              스케일 / 시뮬레이션 / 선택 / 씬 / 천체 / 궤도 / 앱
  ui/                라벨 / 조작 패널 / 정보 패널 / 툴팁 / dom 헬퍼
```

모듈들은 작은 타입드 상태 허브(`core/StateStore.ts`)를 통해 통신하므로 UI 컨트롤과 3D 씬이 중앙 컨트롤러 없이 반응하며, `main.ts`는 아주 작게 유지됩니다.

저장소 루트의 `CHECKLIST.md`에 §18 완료 기준과 UI 표시/숨김 요구사항을 구현 모듈별로 매핑해 두었습니다.
